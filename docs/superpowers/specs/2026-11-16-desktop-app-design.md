# Десктоп-приложение GameCrate (шаг 1: оболочка Tauri)

Дата: 2026-11-16. Обсуждено с владельцем в чате. Макетов не было: вид окна, трея и страницы
«Скачать» описан словами и остаётся решением исполнителя в пределах этой спеки.

## Зачем

Сейчас в GameCrate играют только в браузере. Владелец хочет приложение для Windows, macOS и Linux,
которое даёт игроку три вещи, которых нет у сайта (слова владельца — выбранные им пункты):

1. **Клавиши и полный экран.** Alt+Tab, Win/Cmd, Esc уходят в игру, мышь захватывается нормально —
   на всех ОС, а не только в Chrome. Сейчас захват клавиш — `navigator.keyboard.lock()` в
   `apps/web/src/lib/fullscreen.ts`, он есть только в Chromium (Chrome, Edge, Яндекс Браузер);
   в Safari и Firefox Esc сразу выходит из полного экрана, а системные сочетания уходят в ОС.
2. **Уведомления очереди.** Приложение живёт в трее и показывает системное уведомление «Сервер
   готов», даже если окно свёрнуто или закрыто. Сейчас `QueueWatcher.tsx` шлёт браузерное
   `Notification` (если пользователь его разрешил) и играет короткий звук, а при закрытой вкладке
   игрок через 2 минуты выпадает из очереди (`QUEUE_CLIENT_TIMEOUT_MS`).
3. **Настоящее приложение.** Ярлык, своя иконка, отдельное окно без вкладок и адресной строки.

Это **шаг 1** из трёх. Дальше (не в этой спеке): шаг 2 — прототип нативного плеера на Rust +
GStreamer и замер задержки против браузера; шаг 3 — если выигрыш заметный, нативный плеер
заменяет веб-плеер внутри этой же оболочки. Поэтому оболочка — Tauri (Rust), а не Electron:
нативный плеер потом встанет в тот же процесс.

## Цели

- Приложение под Windows (x64), macOS (Apple Silicon + Intel, universal) и Linux (x64), которое
  открывает наш сайт в своём окне.
- Трей, системные уведомления очереди, приложение не выпадает из очереди при закрытом окне.
- Нативный полный экран и перехват системных сочетаний во время игры.
- Вход работает всеми способами, что есть на сайте, включая Google.
- Сборки на тег, раздача со страницы «Скачать» на сайте, автообновление оболочки.

## Не цели

- Нативный стрим (шаги 2–3). Плеер — тот же Selkies во фрейме, что на сайте.
- Мобильные приложения.
- Подпись кода (Apple Developer ID, Authenticode) — **пока без подписи**, решение владельца. Места
  под подпись в CI оставляем.
- Офлайн-режим и фронтенд внутри приложения: без сети облачный гейминг не работает.
- Автозапуск при входе в ОС, свой магазин, оверлей поверх игры.

## Анти-цели (провал, даже если «работает»)

- Сайт в браузере стал работать хуже или иначе. Все изменения в `apps/web` — только под проверкой
  «мы в приложении», браузерный путь не меняется.
- Любая страница, кроме нашего сайта, получает доступ к нативным командам приложения.
- Приложение держит игрока в очереди или сессии, когда он этого не хочет (например, закрыл окно
  и думает, что вышел, а минуты идут).

## Решения владельца (из чата)

1. **Tauri открывает сайт** (подход A ниже), а не фронтенд внутри приложения и не Electron.
2. **Сборка на GitHub Actions**: там есть раннеры macOS/Windows/Linux, все три сборки — на родной
   ОС, без кросс-компиляции и без своего Mac-раннера.
3. **На GitHub — публичное зеркало всего репозитория** (GitLab push mirror). Владелец предупреждён,
   что это необратимо раскрывает всю историю, адреса инфраструктуры и устройство деплоя, и принял
   риск; разрешение компании (репозиторий сейчас на корпоративном GitLab imtechnologies) — за
   владельцем. **Перед включением зеркала** — проверка всей истории сканером секретов (gitleaks),
   находки показываются владельцу, зеркало включается только после его «ок».
4. **Без подписи кода** на первом этапе.
5. **Раздача с нашего сайта**: страница «Скачать» и манифест автообновления.

## Подходы

| | Как | Плюсы | Минусы |
|---|---|---|---|
| **A. Tauri открывает сайт (выбран)** | Окно Tauri грузит `PUBLIC_URL`; нативное — трей, уведомления, клавиши, ссылки `gamecrate://`, автообновление | Один интерфейс; вход/cookie/очередь работают как есть; деплой сайта сразу обновляет приложение; путь к нативному плееру | На macOS/Linux стрим в системном webview (WebKit), на Linux WebRTC под вопросом |
| B. Tauri с фронтендом внутри | Сборка `apps/web` в бандле, API с другого origin | Грузится без сети | Переделка cookie/CORS/редиректов входа, релиз приложения на каждую правку UI |
| C. Electron | Свой Chromium | Keyboard Lock и WebRTC одинаковы везде | 100+ МБ, к Rust-плееру идти сложнее |

Выбран A: даёт всё нужное шагу 1 и не ломает путь к шагам 2–3. Риск Linux проверяется первой
задачей; если WebRTC в WebKitGTK не заводится, для Linux отдельно рассматриваем C (решение
владельца в тот момент).

## Устройство

### Где живёт код

- `apps/desktop/` в монорепо: Tauri 2 (`src-tauri/` — Rust, `tauri.conf.json`, иконки) и
  маленькая локальная страница-заглушка «Нет связи с сервером — Повторить» на случай, когда сайт не
  открылся. Своего фронтенда нет.
- Изменения на сайте: `apps/web` (обнаружение приложения, мост к нативным командам, страница
  «Скачать», вход через системный браузер), `apps/api` (раздача сборок и манифеста, обмен
  одноразового токена входа), `deploy/` (переменные, бакет).
- CI сборки — `.github/workflows/desktop.yml` в этом же репозитории; GitLab CI не меняется, кроме
  того, что GitLab push-зеркалит репозиторий (ветки и теги) на GitHub.

### Окно и сайт

- Одно главное окно, грузит `PUBLIC_URL` (prod `https://game.brofrong.ru`; адрес зашит в сборку
  при компиляции, dev-сборка — из переменной). Стартовая страница — `/app`; гостя `app.tsx` уже
  уводит на `/login?next=…`.
- **Лендинга в приложении нет** (слово владельца 2026-11-16). В приложении `/` сразу редиректит на
  `/app` (гость оттуда попадает на `/login`); ссылки на главную — «назад» на `/login`
  (`routes/login.tsx`), «На главную» на 404 (`__root.tsx`), `<Navigate to="/">` в
  `session.$id.tsx`, выход из аккаунта — ведут на `/app`, а ссылку «назад на лендинг» на `/login`
  в приложении прячем. В браузере всё как сейчас.
- Переходы на чужие домены (ссылки в Steam, политика конфиденциальности, OAuth) открываются в
  системном браузере, а не в окне. Исключение — `/api/auth/*` на нашем домене.
- User-Agent — стандартный webview + суффикс `GameCrateDesktop/<версия>`, чтобы сайт и логи
  отличали приложение. Определение «мы в приложении» на сайте — по наличию моста Tauri, не по UA.
- Сайт должен пускать origin приложения: если Tauri отдаёт страницы с собственного origin (а не
  `https://game.brofrong.ru`), его добавляем в `ALLOWED_ORIGINS`. Исполнитель проверяет, какой
  origin видит API на каждой ОС.

### Мост сайт ↔ приложение

- Нативные команды доступны **только** страницам `PUBLIC_URL` (Tauri capability с `remote.urls`
  на наш домен). Никаких общих плагинов (fs, shell, http) удалённой странице не открываем — только
  наши команды:
  - `notify(title, body)` — системное уведомление;
  - `set_status(state)` — состояние для трея: `idle | queued(position, total, eta) | starting |
    playing`; от него зависят меню трея и поведение крестика;
  - `enter_game_fullscreen()` / `exit_game_fullscreen()` — нативный полный экран окна + перехват
    сочетаний (ниже);
  - `open_external(url)` — открыть в системном браузере (только `https`);
  - `app_info()` — версия оболочки и ОС.
- На сайте — `apps/web/src/lib/desktop.ts`: `isDesktop()`, обёртки команд, no-op в браузере.
  Существующий код зовёт их рядом с браузерной веткой: `QueueWatcher` (уведомление, статус),
  `fullscreen.ts` (полный экран и клавиши), экран сессии (статус `playing`).

### Трей и уведомления

- Иконка в трее всегда, пока приложение запущено. Меню: «Открыть GameCrate», строка статуса
  («Вы 3-й в очереди · ~5 мин», «Сервер готов», «Идёт игра» — неактивный пункт), «Выйти».
- Клик по уведомлению «Сервер готов» и по иконке — показать и сфокусировать окно.
- **Крестик окна:** если статус `queued`, `starting` или `playing` — окно прячется в трей, а при
  первом таком закрытии показываем уведомление «GameCrate в трее — вы остаётесь в очереди/игре».
  Иначе крестик закрывает приложение. *Решение исполнителя-ассистента* (не владельца): так игрок не
  выпадает из очереди, но и не держит невидимое приложение без причины.
- Окно, спрятанное в трей, продолжает работать (страница не выгружается): `QueueWatcher` шлёт
  heartbeat, поэтому таймаут очереди 2 минуты не срабатывает. Исполнитель проверяет, что webview не
  замораживает таймеры скрытого окна на каждой ОС (WKWebView и WebView2 умеют троттлить) — если
  замораживает, heartbeat переносится в Rust (раз в N секунд дёргает `session.heartbeat`
  с cookie сессии) или отключается троттлинг.
- «Выйти» при статусе `queued`/`playing` — подтверждение «Вы выйдете из очереди / игра
  продолжится до таймаута» — текст решает исполнитель; сессию само приложение не завершает.

### Полный экран и клавиши

- В приложении кнопка полного экрана на экране сессии зовёт `enter_game_fullscreen`: окно
  уходит в нативный полный экран, затем включается перехват. Выход — тот же жест, что сейчас
  (удержание Esc 1,5 с, `ESC_HOLD_MS`) и кнопка меню. Pointer Lock — как сейчас, через браузерный
  API во фрейме.
- Перехват по ОС (механизм — решение исполнителя, первая задача — спайк на каждой ОС):
  - **Windows (WebView2, Chromium):** сначала проверить, работает ли `navigator.keyboard.lock()`
    внутри WebView2 при нативном полном экране — если да, достаточно текущего кода. Если нет —
    низкоуровневый хук клавиатуры, который глушит Win/Alt+Tab для ОС и передаёт их в страницу.
  - **macOS (WKWebView):** `NSApplication.presentationOptions` с `disableProcessSwitching`,
    `hideDock`, `hideMenuBar` на время игры (без разрешения «Универсальный доступ»); Cmd+Q и Cmd+W
    в игре не закрывают приложение. Esc не выходит из полного экрана (это нативный полный экран
    окна, а не HTML Fullscreen API).
  - **Linux:** лучшее из доступного (запрет системных сочетаний через GTK/compositor, если есть);
    полного перехвата под Wayland не обещаем.
- Перехват действует только пока окно в фокусе и в игровом полном экране; при потере фокуса и при
  выходе снимается.

### Вход через Google (и любой провайдер, который не пускает webview)

- Google блокирует вход во встроенных webview (`disallowed_useragent`). В приложении кнопки
  провайдеров, кроме кода на почту, открывают **системный браузер** на нашем сайте
  (`/login/desktop?provider=…`), браузер проходит обычный OAuth, после успеха сайт выдаёт
  **одноразовый токен** (короткий срок, ~2 мин, одно использование) и редиректит на
  `gamecrate://auth?token=…`.
- Приложение ловит ссылку (deep link), открывает в окне `/api/desktop/auth?token=…`, API меняет
  токен на обычную cookie сессии better-auth и редиректит на `/app`.
- Механизм токена — плагин better-auth `one-time-token` (есть в установленной 1.7.10,
  `better-auth/plugins/one-time-token`) или свой маршрут, если плагин не даёт нужного срока или
  хранения хешем (решает исполнитель); токен привязан к пользователю, хранится хешем, после
  использования удаляется.
- Вход по коду на почту работает прямо в окне. Яндекс — в окне, если пускает; если нет — тем же
  путём, что Google. Telegram на проде скрыт — не трогаем.
- *Решение ассистента:* Google включён в шаг 1, а не отложен — иначе часть игроков не войдёт.
  Владелец может отрезать (тогда в приложении просто прячем кнопку Google).

### Ссылки `gamecrate://`

- Схема регистрируется установщиком на всех ОС. Шаг 1 использует `gamecrate://auth?token=…`;
  `gamecrate://open?path=/app/game/123` — открыть страницу сайта в окне (путь только внутри
  нашего сайта). Второй запуск приложения не открывает второе окно, а передаёт ссылку первому
  (single-instance).

### Сборка и релизы

- Версия оболочки — свой semver, тег `desktop-vX.Y.Z` в GitLab (зеркалится на GitHub). Теги
  `vX.Y.Z` сервера не трогаем, и наоборот.
- `.github/workflows/desktop.yml` на тег `desktop-v*`: матрица `macos-latest` (universal
  `aarch64+x86_64`, `.dmg` + `.app.tar.gz` для обновлений), `windows-latest` (NSIS `.exe`),
  `ubuntu-22.04` (`.AppImage` + `.deb`). Кэш Rust. Бюджет — минуты публичного репозитория не
  ограничены.
- **Подпись обновлений** (не кода): ключ updater Tauri (minisign), создаём новый
  (`tauri signer generate`, ключа ещё нет). Приватный ключ — в Bitwarden,
  папка `AI agents`, и в секретах GitHub; публичный — в `tauri.conf.json`.
- После сборки job публикации загружает артефакты и `latest.json` (манифест updater Tauri:
  версия, заметки, подписи, URL по платформам) в хранилище сайта (ниже). Ключ загрузки — в
  секретах GitHub и в Bitwarden.
- Подпись кода: шаги в workflow предусмотрены, но выключены, пока нет сертификатов.

### Раздача и автообновление

- Хранилище: отдельный бакет `cg-desktop` (ещё не создан — создаётся так же, как бакет профилей,
  сервисом `cg-rustfs-bucket`) в уже работающем `cg-rustfs` на главном сервере;
  загрузка из GitHub — отдельным ключом S3 только на запись в этот бакет (если RustFS не умеет
  ключи с ограничением на бакет — маршрут загрузки в API с токеном; решает исполнитель).
- API раздаёт: `GET /download/desktop/latest.json` (манифест для updater) и
  `GET /download/desktop/<версия>/<файл>` (поток из бакета). Публично, без входа.
- Приложение проверяет обновление при запуске и раз в 6 часов; нашло — тихо скачивает и
  предлагает «Перезапустить и обновить» (не во время игры и не в очереди).
- Страница **«Скачать»** `/download`: определяет ОС и показывает большую кнопку под неё, ниже —
  остальные ОС, версия, размер, короткая инструкция «как открыть без подписи» (Windows:
  «Подробнее → Выполнить в любом случае»; macOS: ПКМ → «Открыть»; Linux: AppImage `chmod +x`).
  Ссылка на неё — в меню профиля / приложения и на лендинге (место решает исполнитель). В самом
  приложении ссылку не показываем.

### Безопасность

- Мост открыт только `PUBLIC_URL`; навигация окна на чужие домены запрещена (уходит в браузер).
- `gamecrate://`-ссылки — данные, не команды: `open` принимает только пути нашего сайта, `auth` —
  только токен, который проверяет API.
- Одноразовый токен входа: короткий срок, одно использование, хеш в БД, в логи не пишется, в
  URL системного браузера не попадает (выдаётся уже после OAuth, только в редирект на
  `gamecrate://`).
- Публичное зеркало: gitleaks по всей истории до включения; секреты в репозиторий по-прежнему
  не кладём; GitHub-секреты (ключ updater, ключ загрузки) — только в Actions secrets и Bitwarden.

## Состояние на 2026-11-16

Ничего из этого ещё нет: GitHub-зеркала, репозитория на GitHub, бакета `cg-desktop`, ключа updater,
`apps/desktop`. Всё создаётся по ходу работ. Спайк (задача 1) входит в план и идёт первым: дальше
план строится на предположении, что стрим работает на Windows и macOS; если Linux не тянет —
остальные задачи для Windows/macOS не меняются, Linux-сборка выпускается с пометкой «без стрима»
или откладывается по решению владельца.

## Порядок работ (для плана)

1. **Спайк-проверка** на трёх ОС (Mac владельца + раннеры GitHub/виртуалки): окно Tauri с сайтом,
   вход по коду, запуск сессии на brofrong, идёт ли стрим (особенно WebKitGTK), троттлинг
   скрытого окна, `keyboard.lock()` в WebView2. Итог — короткая записка в спеке; если Linux не
   тянет стрим — вопрос владельцу.
2. Оболочка: окно, трей, уведомления, крестик, single-instance, deep link, заглушка без сети.
3. Мост и изменения сайта (`desktop.ts`, `QueueWatcher`, статус, полный экран и клавиши).
4. Вход через системный браузер + одноразовый токен (API + web + приложение).
5. Раздача: бакет, маршруты API, страница «Скачать».
6. GitHub: gitleaks → «ок» владельца → push mirror → workflow, ключи, первый тег
   `desktop-v0.1.0`.

## Что нужно от владельца по ходу

- GitHub-аккаунт или организация для зеркала и имя репозитория; токен для push mirror (сохраним
  в Bitwarden).
- «Ок» после отчёта gitleaks — до включения зеркала.
- Включение бакета и переменных на главном сервере — как обычный деплой, с его согласия.

## Оставлено исполнителю

- Вид окна, трея, иконок трея, страницы «Скачать» и заглушки без сети — в стиле бренда GameCrate.
- Конкретные механизмы перехвата клавиш по ОС (по итогам спайка).
- Плагин better-auth `one-time-token` или свой маршрут.
- Загрузка в бакет ключом S3 или через API.
- Минимальные версии ОС (по умолчанию — что поддерживает Tauri 2: Windows 10+, macOS 11+,
  Ubuntu 22.04+).
