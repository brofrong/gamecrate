# Свои игры

Фанатские ПК-порты вне Steam (спека `docs/superpowers/specs/2026-11-03-free-games-design.md`).
Каталог `games/<slug>/` — одна игра: описание для сайта и агента, сборщик и скрипт запуска.
Пакет собирается на воркере скриптом `deploy/add-game.sh` и лежит там в
`<GAMES_DIR>/<slug>/<version>/` (на brofrong `/raid/cloud-gaming/games`). В сессии пакет
смонтирован только для чтения в `/opt/cg-game`, игра запускается через `/opt/cg-game/run`.

## Никаких файлов Nintendo в репозитории

ROM (`*.z64`, `*.n64`, `*.v64`), архивы активов (`*.o2r`) и каталоги `roms/` не попадают ни в git,
ни в образы, ни на сервер вместе с репозиторием. Их закрывают `.gitignore`, `.dockerignore` и
исключения `rsync` в `deploy/deploy.sh` и `deploy/add-game.sh`. ROM передаётся только аргументом
`--input` скрипта: он копируется во временный каталог воркера и удаляется ловушкой `trap` на
любом выходе. В пакете остаются только активы, которые сборка извлекла из ROM (`oot.o2r` у SoH).
Пакет с ROM внутри (по расширению или копию входного файла под любым именем — по размеру и
SHA-256) `add-game.sh` не выпускает.

## Что лежит в `games/<slug>/`

| Файл | Что |
| --- | --- |
| `game.json` | описание игры, схема `OwnGameManifest` (`packages/rpc/src/ownGames.ts`) |
| `site/` | картинки сайта: `header.jpg` 920×430, `hero.jpg` 1920×620, `cover.jpg` 600×900 и скриншоты из `site.screenshots`, 1920×1080, JPEG |
| `builder.Dockerfile` | сборщик: `FROM ${SESSION_IMAGE}` (те же системные библиотеки, что в сессии) плюс компилятор; нужен `ENTRYPOINT []` |
| `build.sh` | сборка внутри сборщика |
| `run` | запуск в сессии: окружение и `exec` бинарника |

Поля `game.json`:

- `appId` — от `1900000000` (`OWN_APP_ID_MIN`), следующий свободный номер;
- `slug` — `^[a-z0-9][a-z0-9-]{0,31}$`, совпадает с именем каталога;
- `version` — версия пакета, `^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$`. Новая сборка того же
  upstream — новый суффикс (`9.3.1-1` → `9.3.1-2`);
- `binary` — имя бинарника в пакете, без `/`;
- `upstream` — репозиторий и тег порта;
- `inputs` — входные файлы сборки (`name` — как `slug`, `label` — подсказка);
- `site` — описание (абзацы через пустую строку), таблица «Управление», ссылка на проект,
  скриншоты;
- `requirements` — минимум видеопамяти, памяти и потоков CPU по умолчанию (меняются в админке).

Тест `packages/rpc/test/ownGames.test.ts` проверяет, что `games/soh/game.json` декодируется и
все картинки на месте. Для новой игры добавьте её туда же.

## Контракт `build.sh`

Сборщик запускается как `docker run --rm --init --user 1000:1000 <сборщик> /game/build.sh /input /out`:

- `/game` — копия `games/<slug>` (только чтение);
- `/input/<name>` — входные файлы из `--input <name>=<путь>` (только чтение);
- `/out` — пустой каталог пакета (запись). В нём должны оказаться исполняемый `run` и `binary`.

Сеть у сборщика есть. Дерево сборки держите во временном каталоге контейнера — оно уходит
вместе с `--rm`. Копии входных файлов удаляйте ловушкой `trap` в самом `build.sh`. Библиотеки,
которых нет в образе сессии, `build.sh` не собирает: `add-game.sh` после сборки запускает `ldd`
бинарника в `SESSION_IMAGE` и докладывает недостающее из сборщика в `/out/lib` (не больше 5
проходов). `run` должен выставить `LD_LIBRARY_PATH=/opt/cg-game/lib`.

## Как добавить свою игру

1. Каталог `games/<slug>/`: `game.json`, `site/`, `builder.Dockerfile`, `build.sh`, `run` (пример —
   `games/soh`). Картинки — свои кадры со своей сессии.
2. Строка в тесте `packages/rpc/test/ownGames.test.ts`, `bun test packages/rpc`.
3. Сборка пакета на воркере:

   ```sh
   ./deploy/add-game.sh <slug> [--host <ssh-хост>] [--input <name>=<путь>]... [--rebuild]
   ```

   Пакет этой версии уже есть — скрипт выходит («уже есть»). `--rebuild` пересобирает ту же
   версию, если на ней не идёт сессия. На хосте остаются новая и предыдущая версии.
4. Деплой (`./deploy/deploy.sh`) — сайт получает описание и картинки, агент видит пакет.
5. В админке «Игры» → «Свои сборки» — «Открыта игрокам».

## Ship of Harkinian (`soh`)

```sh
./deploy/add-game.sh soh --input rom=<путь к ROM Ocarina of Time>
```

ROM — N64 NTSC-U 1.2 (`.z64`, `.v64` или `.n64`: `build.sh` приводит порядок байт к `.z64`) или
другой из списка SoH. Полная сборка — около 20 минут на 12 потоках brofrong. Подробности спайка —
«Итоги Task 1» в `docs/superpowers/plans/2026-11-03-free-games.md`.
